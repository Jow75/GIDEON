# Gideon Core v1.0.0 Release Notes

Welcome to the **v1.0.0** release of Gideon Core. 

This release marks the formal freezing of our underlying distributed architecture. After rigorous testing (Mega Phases 1-4, RC1 Stabilization, and Staging Validation), the core foundation is now considered production-ready.

## What's New in v1.0.0

- **Transport-Agnostic EventBus:** The orchestration engine now runs entirely on an asynchronous, decoupled EventBus. Supported transports: Local (memory) and Redis (distributed).
- **State Synchronization (`SyncManager`):** Safely coordinates distributed state (`world_state`) across multiple Gideon nodes using a Last-Write-Wins (LWW) conflict resolution strategy.
- **Persistence Abstraction (`HistoryStore`):** The conversation and memory persistence layer is fully abstracted. Includes `SQLiteHistory` (development) and `PostgresHistory` (production).
- **Long-Term Memory (`QdrantMemory`):** Integrated with Qdrant for semantic search and experiential memory recall.
- **Security & Authorization (`Guardian`):** Complete integration of JWT-based authentication for all REST and WebSocket connections, backed by the `Guardian` firewall to reject malicious skills or payload injections.
- **Remote Execution:** Tasks and Skills can now be executed across the cluster. The Commander node can delegate computationally heavy workloads to dedicated Execution Workers.
- **Docker & CI/CD Readiness:** Fully containerized with a `docker-compose.yml` that stands up Gideon, Redis, Postgres, and Qdrant out-of-the-box.

## Engineering Freeze
The following contracts are now **frozen**:
- EventBus Protocol
- HistoryStore Interface
- Skill Manifest Schema
- JWT/Auth Contract
- Remote Execution Protocol
- SyncManager Event Formats
- Node Heartbeat Schema

Any breaking changes to these contracts in the future will undergo a formal deprecation period with Semantic Versioning.
